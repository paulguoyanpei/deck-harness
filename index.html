01 / 做法

三个入口，
一个大脑。

保持任务与模型不变，只替换模型外部的运行方式。观察相同能力如何被不同的上下文组织、工具链和反馈机制放大或损耗。

DS

DeepSeek API

以直接 API 调用作为轻量基线。路径短、干预少，观察模型在最少系统支持下的原始输出。

PROMPT → MODEL → FILE
MY HARNESS

自研 Harness

把规划、素材处理、生成与检查组织成可控流程，让模型在明确边界与反馈回路中完成任务。

PLAN → BUILD → INSPECT → REFINE
CC

CC

使用通用编码 Agent 的完整执行环境，观察成熟工具使用与自主决策对成片的影响。

AGENT → TOOLS → ARTIFACT
02 / 动机

模型能力，
不等于交付能力。

当 Backend LLM 相同，结果仍然不同，差异就更可能来自模型外部的系统设计。

01

隔离变量

不再把所有差异笼统归因于“模型更聪明”，而是把 Harness 单独拿出来观察。

02

理解放大器

上下文、工具、检查机制和迭代策略，决定模型能力能否稳定转化为作品。

03

找到工程抓手

与其等待下一个模型，不如先优化今天就能控制的执行系统。

03 / 效果

相同能力，
出现不同轨迹。

这次对比更关注“结果为什么这样形成”，而不只看最后一页是否漂亮。

Harness 改变了能力被调用的方式。

差异不仅体现在视觉，也体现在过程是否可观察、可修正、可复现。

DS

直接、轻量，适合作为原始能力基线；结果更依赖一次提示中的信息密度。

我的 Harness

过程被拆解为明确阶段，检查点与反馈回路让输出更可控，也更容易定位问题。

CC

工具使用更自主，能覆盖完整交付链路；通用性强，同时保留更多 Agent 自主决策。

04 / 结论

模型决定上限，Harness 决定你能稳定拿到多少。

这不是“谁的模型更好”的测试，而是一次系统设计实验：同一个模型，经由不同执行框架，会形成不同的过程质量、作品质量与可复现性。

05 / 下一步

把一次对比，
变成可重复评测。

盲评成片

隐藏生成方式，让评审只基于信息结构、视觉质量与叙事完整度评分。

量化过程

记录耗时、Token、工具调用、人工介入与返工次数，比较真实交付成本。

做消融实验

逐一关闭规划、检查、渲染反馈等模块，确认 Harness 中真正有效的部分。
